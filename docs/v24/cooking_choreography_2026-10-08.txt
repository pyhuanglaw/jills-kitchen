我已經開始實際玩私人測試版。

第一天實玩，我覺得現在明顯比較像我原本想像中的料理遊戲。

因此目前先依以下決策繼續：

1. 前三天 throughput 下降：先不要修

模擬顯示前三天新廚房服務客人約少 18%，但我真人實玩第一天後，目前的料理節奏是正面的。

不要為了把 Day 1 的模擬服務人數補回 main，而去：

* 加快 Jill 移動
* 大幅縮短料理時間
* 增加早期 batch
* 改客人耐心
* 改客流
* 改價格／收入
* 讓員工提早出現
* 讓所有廚師什麼都會

目前保留現況。

早期 Jill 一個人真的在廚房各站之間料理，本身可以是合理的 early-game pacing；之後聘到廚師，效率提升才會有成長感。

除非後續真人實玩出現「主要時間都在無聊等 Jill 走路」的問題，否則不要因為模擬數字自行修快。

⸻

2. 前期只有 Jill 能處理部分 PLATING：目前不要因此讓所有廚師都會裝盤

不要為了修 throughput，直接給每個廚師 PLATING 能力。

維持 proficiency / specialization 的意義。

我會繼續實玩到有員工的階段，確認實際感受。

真正的驗收不是數字，而是我能不能自然理解：

「阿德正在做那個，所以我來處理這個。」

如果前期 PLATING bottleneck 真人玩起來真的煩，再針對 proficiency / recruitment progression 處理，不先用全員 PLATING 解掉。

⸻

3. 值班表保留

被排成「待命」的廚師就休息，不要偷偷工作。

值班中的廚師才參與 kitchen AI。

目前這個方向保留。

⸻

4. 舊的「燒焦」相關文字／規則要列入清理

新 Cooking System 已經沒有燒焦失敗，因此：

* 衛生檢查員「別燒焦」
* review / 結算裡仍假設會燒焦的文字
* 其他舊 cooking failure 文案

都已經成為 legacy inconsistency。

請完整 audit 所有舊「燒焦 / burn / 焦掉 / timing failure」相關 reference。

先整理：

* 出現位置
* 現在功能
* 是純文字還是實際影響條件／評分
* 建議的新語意

如果只是明顯過時文案，可以改成符合新系統的內容。

如果會改變衛生檢查、評價、經濟或其他系統的實際 balance，先列出再決定，不要偷偷重做整套系統。

⸻

5. PREP 第三個位置不要硬塞第三塊砧板

既有冷盤台只能自然容納兩塊砧板，就不要為了讓資料表達到 PREP=3 而破壞目前廚房。

原廚房視覺優先於預先寫死的容量數字。

PREP mature capacity 暫時可以維持 2。

未來如果實際 simulation / 真人遊玩證明 PREP 長期成為不合理瓶頸，再找符合現有廚房空間的升級方式。

不要現在硬加第三塊板。

⸻

6. 現在優先讓我真人測 gameplay，不要再為模擬數字大改

接下來請維持私人測試版，修：

* 明確 bug
* workflow 顯示錯誤
* handler 顯示錯誤
* 點擊／touch 問題
* 動畫或食物位置不合理
* player/staff claim race
* 存檔問題
* mobile layout
* 明顯 legacy inconsistency

不要因為 simulator 的 throughput 差異主動重新 balance 核心料理節奏。

我現在最需要觀察的是：

1. 我是否永遠知道下一步去哪。
2. 我是否永遠知道誰正在處理。
3. 我想介入時能不能自然介入。
4. 我不想管時員工能不能自然接手。
5. 多道菜一起來時，我是在思考優先順序，而不是搞不懂 UI。
6. 有廚師之後，是否從「自己做菜」自然變成「一起經營廚房」。
7. 我離開廚房去看貓／客人／故事時，會不會因此受到不合理懲罰。

目前第一天的實玩方向是正確的。

先不要把一個已經開始好玩的東西，為了追平舊版模擬數字又調回去。
PLATING 是一般廚師四大 proficiency 之一，不設「前期只有 Jill 能裝盤」的通則。廚師是否能／多主動處理 PLATING，由其 PLATING proficiency 決定。不要因舊 chefCan 的 Jill-first 規則，把 PLATING 人為鎖給 Jill。只有明確指定的 Signature 關鍵步驟可以保留 Jill 專屬／優先。
我剛實際玩了料理測試版第一天。

整體新的 Cooking workflow 已經比舊版更像我想要的料理遊戲；目前不要重做 workflow、station、guidance、staff handoff，也不要增加玩家操作。

但我發現一個很明顯的問題：

黃金蛋炒飯在 HOT 時，看起來像一份已經完成的炒飯直接出現在料理位置，然後慢慢變大。

這不夠像「Jill 正在做炒飯」。

所以現在要補的是：

Cooking Visual Choreography

玩家少按，不代表 Jill／廚師少做

核心規則：

菜色可以很多，廚房工作的語法要很少；但每一道菜在工作站裡，必須看得出它正在經歷自己的料理過程。

這一輪不要增加任何 player-perceivable step。

例如黃金蛋炒飯仍然只有：

HOT → PLATING

玩家仍然只需要：

1. 點炒飯
2. 點 HOT
3. 做完後點 PLATING

但 HOT 這一站內部，Jill／廚師必須自己完成真正像炒飯的視覺過程。

⸻

HARD RULES

1. 禁止用「完成品 sprite 從小慢慢變大」當主要 cooking animation。

scale 可以有非常輕微的呼吸／動態，但不能拿「變大」代表料理進度。

2. 每一道料理至少要有：

* raw / initial visual
* 1 個以上 visible transformation
* finished-at-this-station visual

複雜料理最好 3–5 個 internal visual beats。

3. internal visual beat：

* 不增加玩家 click
* 不增加 workflow step
* 不增加 QTE
* 不增加 timing challenge
* 不增加 failure / burning
* 不需要玩家記配方

它只是 Jill／廚師真的在做事。

4. 角色的手部／工具動作與食物狀態必須有因果關係。

例如：
Jill 倒蛋 → 鍋裡才出現蛋。
Jill 加飯 → 飯才出現。
Jill 翻牛排 → 熟面才翻上來。

不要食物自己憑空 morph，而角色只在旁邊 generic 揮手。

5. 可以重用底層動畫 primitive：

* chop
* mix
* stir
* toss
* flip
* pour
* spread
* place
* garnish
* whisk
* shake
* slice

但每道料理的 choreography 必須由下面的 dish spec 決定，不能只按照 workflow family 給所有 HOT 菜同一套動畫。

6. 食物在料理過程中可以簡化，不要求高成本逐幀動畫。

可以使用：

* ingredient layer 出現／消失
* 色澤漸變
* 位置小幅移動
* steam
* pan toss
* flip
* sauce layer spread
* garnish appearing
* container change

重點是玩家一眼能理解「現在真的在做這道菜」。

A. Restaurant 22 dishes

1. 黃金蛋炒飯

Workflow：HOT → PLATING

HOT：

* 開始時是空鍋／少量油，不准直接出現完成炒飯。
* Jill／廚師打蛋或倒入蛋液。
* 鍋內先出現黃色半凝固蛋。
* 加入白飯。
* 加入蔥／配料。
* 使用鍋鏟翻炒，或做小幅度 pan toss。
* 白飯＋蛋從分離狀態逐漸變成均勻金黃色炒飯。
* 最後才成為現在的完成炒飯 visual。

PLATING：

* 炒飯從鍋移到盤中。
* 整形成自然的一份炒飯。
* 最後少量蔥花／裝飾。

禁止：一開始就是完成炒飯，然後 scale 變大。

現在只是再補一句：

3. 哪些 visual primitive 是共用的。

補充一個重要修正：我實際玩後發現，目前 PLATING 的空間邏輯是錯的。

請先不要把 PLATING = Pass 固定工作站 當成產品 canon。

我實際看到的行為是：

HOT 做完
→ 食物自己跑到別的位置／備料台附近
→ 我點裝盤
→ Jill 才走去做一個裝盤動作
→ 最後到 Pass

這不對。

而且目前 tests/cooking_tests.py 本身也把舊邏輯寫成 acceptance：
HOT 完成後 cue Pass，玩家點 Pass，Jill fetch，然後 plates it。

請連 architecture 與 tests 一起修正，不要只改 animation。

PLATING 的正確定義

PLATING 仍然是玩家可理解的 workflow step：

HOT → PLATING

但 PLATING 不是「食物自己移動到某個 plating station」。

它代表：

角色拿一個空盤，走到上一個料理站已經完成的食物旁，把食物真正裝進盤子／擺盤，然後把完成的盤子送到 Pass。

因此要把：

PLATING = food goes to Pass

改成：

PLATING = handler fetches plate → handler goes to finished food → plates there → handler carries completed plate → Pass

⸻

以黃金蛋炒飯為標準範例

正確完整流程：

1. HOT

Jill 在炒台完成炒飯：

空鍋／油
→ 蛋
→ 飯
→ 配料
→ 翻炒
→ 完成炒飯

HOT 完成後：

炒飯繼續留在原本那個鍋／炒台 slot。

不要瞬移。
不要自己跑去 PREP。
不要自己跑去 Pass。
不要先變成盤裝完成品。

Ticket：

✓ 熱區 → ● 裝盤
下一步：裝盤 · 等待處理

⸻

2. 玩家選擇 PLATING

玩家 focus 黃金蛋炒飯。

這時 guidance 不應該表達：

「把炒飯送去 Pass。」

而應該讓玩家理解：

「現在可以把這鍋炒飯裝盤。」

如果玩家正式指派 Jill 做 PLATING：

Jill claim PLATING step。

⸻

3. Jill 先取得空盤

Jill 應該有一個很短、自然的：

拿空盤

動作。

盤子可以來自目前廚房合理的 plate stack / plating supply。

不需要玩家另外點盤子。

玩家只需要下達「做 PLATING」這個決定。

「拿盤」是 Jill 自動完成的 internal choreography。

不要因此增加第四個 gameplay step。

⸻

4. Jill 走回炒好的食物

Jill 拿著空盤：

→ 走到剛才完成炒飯的 burner / wok。

這時：

* 炒飯仍然在原鍋
* 鍋仍然在原 burner
* Jill 手上／動作狀態有盤子
* 食物沒有 teleport

⸻

5. 真正的 plating animation 在這裡發生

Jill 在炒台旁：

→ 用鍋鏟把炒飯盛入盤中
→ 鍋裡的炒飯量減少／消失
→ 盤中的炒飯出現
→ 整理形狀
→ garnish / 蔥花

這一刻才叫 PLATING。

不是食物已經跑到 Pass 之後，角色再演一個抽象的 plating gesture。

⸻

6. 完成後 Jill 拿著成品去 Pass

裝盤完成：

Jill 手上現在是：

完成的黃金蛋炒飯 plate

然後：

→ Jill 從炒台走到 Pass
→ 把完成盤放到 Pass
→ waiter 才能 pickup / serve

所以 Pass 的角色是：

completed-food handoff / pickup point

而不是：

cooking/plating station。

這兩個概念請徹底分開。

⸻

空間連續性 HARD RULE

任何料理從上一個 station 完成到 PLATING，都必須回答：

「這份食物現在物理上在哪裡？」

答案不能突然改變。

例如：

牛排 HOT 完成：
牛排仍在 HOT pan/grill。

烤雞 OVEN 完成：
烤雞仍在 oven tray / oven output position。

沙拉 PREP 完成：
拌好的沙拉仍在 PREP bowl。

披薩 PIZZA OVEN 完成：
披薩仍在 pizza oven output / tray。

它們都不應該因為 workflow 進入 PLATING 就 teleport 到 Pass 或另一張桌子。

⸻

不同上一站的 PLATING

HOT → PLATING

例：

* 黃金蛋炒飯
* 番茄義大利麵
* 南瓜濃湯
* 松露燉飯
* 蒜香蘑菇
* 炸雞塊

角色：

拿盤／碗
→ 走到 HOT finished food
→ 盛出／夾出／倒出
→ garnish
→ 拿成品去 Pass

⸻

例：

* 田園沙拉
* 生火腿沙拉
* 提拉米蘇
* 焦糖布丁
* 起司拼盤
* 生蠔

角色：

拿 serving plate / bowl
→ 到 PREP finished food
→ transfer / assemble / unmold / arrange
→ garnish
→ 拿成品去 Pass

⸻

例：

* 巴斯克
* 舒芙蕾
* 德國豬腳

→ 到 oven / oven output
→ 取出完成食物
→ transfer / slice / garnish
→ 拿成品去 Pass

如果視覺上直接從 oven 拿 tray 比較合理，可以先取 tray，再在 oven adjacent usable surface 完成 plating。

人搬食物，不是食物自己瞬移。

角色：

→ 帶 plate / board 去 pizza oven
→ 取出 pizza
→ 放上 board

→ garnish

⸻

PLATING capacity 的重新解釋

我們原本有：

PLATING capacity 1 → 2 → 3

不要直接刪掉 capacity concept。

但它不再代表：

「Pass 有幾個地方可以讓食物 teleport 過去裝盤。」

它應代表：

同時能進行多少個 finishing / plating operation，以及有多少可用的 plate/pass landing capacity。

請 audit 現有 Pass、plate positions、heat lamps、plate stack 與角色動線後，用最小 architecture 改動重新定義。

如果需要區分：

* plating action capacity
* Pass completed-plate holding capacity

可以內部分開。

但玩家不需要看到兩套複雜系統。

⸻

Staff 同樣遵守

如果小林師傅接 PLATING：

不能：

炒飯 HOT 完成
→ 炒飯瞬移
→ 小林在 Pass 等它。

而是：

炒飯留在 burner
→ ticket 顯示 下一步：裝盤 · 小林師傅前往中
→ 小林取得盤子
→ 小林走到炒飯
→ 小林把炒飯盛進盤子
→ 小林拿完成盤去 Pass。

因此 handler 才是真的「接手這份料理」。

⸻

Guidance 也要跟著改

現在 tests 裡的：

HOT finished → pass is cued

需要修改。

HOT finished 後，focus 該料理時，主要 cue 應該圍繞：

* 原本完成食物所在的位置
* PLATING 可以開始
* handler 將前往該 finished food

不要讓玩家誤以為「下一站是把食物 teleport 去 Pass」。

UI workflow 仍然可以寫：

✓ 熱區 → ● 裝盤

因為對玩家而言這仍然是 PLATING step。

只是 physical choreography 不再把 PLATING 錯誤等同 Pass。

⸻

Test 必須一起改

目前 cooking_tests.py 有 acceptance 明確寫：

done, it waits on the fire
the pass lit
a tap on the pass
Jill plates it
plate goes the old way

這個 test 現在與新產品決策衝突。

請改 acceptance test，至少驗證：

1. HOT 完成後，food visual 仍在原 HOT slot。
2. PLATING claim 不會讓 food teleport。
3. handler 取得 plate。
4. handler 實際走到 finished food。
5. plating animation 在 finished-food location 發生。
6. raw/cooked food visual 從鍋／tray 轉移到 plate。
7. plating 完成後，handler 才帶 completed plate 前往 Pass。
8. completed plate 到 Pass 後 waiter 才可 pickup。
9. 整段過程 work node identity 不變。
10. staff plating 走完全相同 physical logic。
11. batch ×N 要合理產生對應完成份數，但仍是一個 work node。
12. save / old-save / handoff / capacity 不 regression。

⸻

與上一則「全料理動畫」規格合併

上一則每一道料理的 PLATING choreography 都按照這個新 architecture 解讀。

例如牛排：

PREP
→ HOT 煎熟
→ 牛排留在 HOT
→ handler 拿盤走到牛排
→ transfer / slice / sauce / garnish
→ handler 拿完成牛排去 Pass。

鴨胸：

PREP score
→ HOT skin sear / flip / rest
→ 鴨胸留在 HOT finished position
→ handler 帶盤過來
→ slice
→ arrange slices
→ sauce
→ handler 帶完成盤去 Pass。

沙拉：

PREP 切／拌
→ salad 留在 PREP bowl
→ handler 帶 serving bowl / plate 過來
→ transfer
→ garnish
→ Pass。

因此：

PLATING 是角色去料理旁邊把它變成一道可以上桌的菜。

而：

PASS 是一道已經裝好盤的菜交給外場的位置。

兩者不要再混在一起。

最重要的空間規則：

食物不會自己去下一個地方。人去拿它、處理它、搬它。

這才是目前 Cooking System 接下來所有動畫與 handoff 的基礎。
