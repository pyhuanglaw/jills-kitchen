1. 最大原則：不要破壞現在已經好的東西

把新的料理玩法放進現在的 Jill’s Kitchen。

為了新的料理玩法重新做一個 Jill’s Kitchen。

* 美術
* 比例
* 色調
* counter
* range
* oven
* prep area
* coffee area
* Pass
* heat lamps
* 小物件
* 人物比例
* 空間感
* animation 氣質

全部優先保留。

如果 gameplay architecture 與現有漂亮廚房發生衝突：

優先修改 gameplay implementation，不要修改廚房來遷就 gameplay。

2. 不准再出現舊 prototype 的視覺語言

今晚任何玩家可見成果都不要出現：

* 方格 station
* 彩色地板區
* 巨大的 HOT / PREP / PLATING 按鈕
* 巨大的 CHOP / COOK / SERVE
* 大型 progress circle
* arcade HUD
* Overcooked 式工作站 icon
* 滿畫面的箭頭

Passive guidance 安靜；selected dish 才明顯。

3. 不要把 debug UI / placeholder 當成最後 UI

開發時可以使用 debug overlay。

但給我看的 private build / screenshot：

必須是玩家會看到的 UI。

如果某個 UI 還只是 debug / placeholder：

清楚標記。

不要因為功能能跑，就把工程測試畫面包成「新版料理完成」。

⸻

4. 不要為了新 architecture 把原本料理動畫變少

新 workflow 是：

減少玩家操作步驟。

不是：

減少 Jill 實際做菜的細節。

例如：

牛排玩家只需要：

PREP → HOT → PLATING

但 Jill 在 HOT 裡仍然可以：

* 放入鍋中
* 煎
* 翻面
* 等待
* 起鍋

這些可以是自動 animation。

義大利麵玩家可以只操作：

HOT → PLATING

但畫面仍然可以看到鍋、蒸氣、瀝乾或醬汁相關動作。

玩家少按 ≠ Jill 少做。

如果舊版已有漂亮的料理 animation，優先保留／重用。

⸻

5. 不要讓料理 UI 蓋住餐廳

我希望玩家是在看 Jill’s Kitchen 做菜，不是在看 dashboard。

Active ticket 只放真正必要資訊：

* dish
* quantity
* workflow
* current step
* next step
* handler

不要順便加入：

* 秒數
* efficiency %
* quality %
* recipe ingredient checklist
* staff stats
* XP meter
* combo
* score
* star rating
* 多餘數值

除非既有正式版本來就需要。

6. 不准為了「好玩」偷偷增加懲罰

* 客人生氣倒數
* miss timing
* combo

* QTE
* 快速連點
* 拖曳精準度
* 做錯步驟失敗

如果料理完成一步：

安全等待。
