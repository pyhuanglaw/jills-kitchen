CUSTOMER IDENTITY & SPATIAL LINKING PASS
讓「名字、訂單、對話、桌位、場景人物」真正連成同一個人

這是一個我想改很久的 usability / immersion 問題。

目前 Jill’s Kitchen 裡：

- 訂單卡有 customer / party name
- 訂單卡有 T1 / T7 / T35 等 table number
- 對話會顯示 speaker name
- restaurant scene 裡也真的有 customers 坐在桌邊
- named regulars / story characters 也會實際來餐廳

但作為玩家，我幾乎完全無法把這些資訊對起來。

例如：

我看到：

T35｜陳家

但我不知道 T35 在畫面上到底是哪一桌。

我看到某個角色說話，
但我不知道畫面裡到底是哪一個人在說話。

我看到一桌 8 個 customers，
但我不知道：

- 他們是誰
- 哪一個是 order card 上的名字
- 哪一個剛剛講過話
- 有沒有 named regular 坐在裡面

結果目前：

ORDER SYSTEM
DIALOGUE SYSTEM
CUSTOMER SPRITES
TABLE SYSTEM
CHARACTER SYSTEM

雖然資料可能彼此有關，
但玩家感知上是完全分離的。

這會讓 customers 看起來像：

「來、吃、走的 anonymous sprites」

而不是 Jill’s Kitchen 裡真正存在的人。

目前我在場景裡幾乎只穩定認得：

Jill
Dylan

這需要改善。

CORE DESIGN PRINCIPLE
━━━━━━━━━━━━━━━━━━

請建立：

【NAME ↔ PERSON ↔ TABLE ↔ ORDER ↔ DIALOGUE】

之間的雙向 spatial linking。

最重要的 UX 原則：

【只要玩家在任何 UI 看見一個人的名字，
就應該能很容易找到這個人現在在哪裡。】

反過來：

【只要玩家在 restaurant scene 看見一個 customer，
也應該能很容易知道這個人是誰。】

不要要求玩家自己記：

T35 在哪裡。

不要要求玩家自己比對：

order name 和 sprite。

不要讓 dialogue speaker 只是浮在 UI 裡的一個名字。

━━━━━━━━━━━━━━━━━━
1｜ORDER CARD → TABLE
━━━━━━━━━━━━━━━━━━

目前 order card 已經有：

T1
T7
T35
etc.

請讓 order card / table number 可以點擊。

例如玩家 tap：

T35

或 tap 整張 order card 的適當區域，

系統應該：

1. 自動切換到該桌所在的 room
2. camera / viewport focus 到該 table
3. 該 table 短暫 highlight
4. 必要時該桌 customers 也有非常短暫、低干擾的 focus cue

例如：

- subtle glow
- outline
- pulse
- table-number badge
- brief name label

持續約 1–2 秒即可。

不要做成長期 flashing UI。

玩家應該立刻理解：

「喔，T35 就是這桌。」

如果 T35 在：

Main Hall
Side Hall
Lounge
Private Dining

都應該能正確切換。

━━━━━━━━━━━━━━━━━━
2｜TABLE → ORDER / PARTY IDENTITY
━━━━━━━━━━━━━━━━━━

顯示目前 existing order / party name 即可。

不要做大型 customer-management panel。

只需要讓玩家知道：

【這桌就是誰。】

如果現有 order card 還存在，
可以提供非常自然的 visual link / focus，
但不要跳出複雜 menu。

━━━━━━━━━━━━━━━━━━

玩家應該可以直接 tap customer sprite。

tap 後至少顯示：

【名字】

核心不是建立完整人口資料庫。

核心是：

【我點這個人，我知道他是誰、坐哪桌。】

━━━━━━━━━━━━━━━━━━
4｜DIALOGUE → SPEAKER
━━━━━━━━━━━━━━━━━━

這是非常重要的一部分。

目前 dialogue 出現：

「王先生：……」

玩家讀得到名字，
但未必知道王先生現在坐在哪裡。

請讓 dialogue speaker identity 可以被 spatially located。

最直覺方案：

tap speaker name / portrait / dialogue header

→ 自動切換到 speaker 所在 room
→ focus speaker
→ speaker 短暫 highlight
→ speaker name 短暫出現在人物附近

例如：

[王先生]

1–2 秒後自然 fade。

如果 dialogue 發生時 speaker 已經在目前 viewport，
也可以直接 focus / highlight，
不需要 unnecessary room transition。

━━━━━━━━━━━━━━━━━━
5｜DIALOGUE 發生時最好直接建立視覺關聯
━━━━━━━━━━━━━━━━━━

不要完全依賴玩家主動點。

如果某個 customer 在場景裡說話，

dialogue 開始時可以考慮：

- very subtle speaker highlight
- tiny temporary name tag
- short focus cue
- portrait ↔ sprite visual association

不要讓整個場景停住或大幅 zoom。

只是讓玩家眼睛自然知道：

【現在是這個人在講話。】

尤其 named regular / story character，
這非常重要。

玩家經過幾次之後，
應該自然開始認得：

「喔，這個就是 Sophie。」

而不是永遠只認 dialogue portrait。

━━━━━━━━━━━━━━━━━━
6｜NAMED CHARACTERS 要比 GENERIC CUSTOMERS 更容易辨認
━━━━━━━━━━━━━━━━━━

對：

- regulars
- story characters
- recurring guests
- special guests

↔ scene sprite
↔ dialogue portrait
↔ table
↔ order

portrait 長這樣，

加入少量 identity cues：

- hair
- glasses
- clothing silhouette
- signature color / garment
- accessory
- age cue
- hairstyle

不要要求 scene sprite 完全複製 portrait。

只需要讓 recurring characters 有：

【recognition anchor】

例如玩家看過 5 次王先生之後，
應該有機會不點名字就猜得到：

「那個應該是王先生。」

這對角色 attachment 非常重要。

order
dialogue
sprite

不要建立大型新系統。

如果中途已經有可見 interaction，
請提供 mobile screenshot / evidence，
但 REPORT ≠ STOP；
可以繼續做不受影響的 implementation。

PRIORITY / RELEASE PLACEMENT UPDATE

前一則 Customer Identity & Spatial Linking Pass 不放到 P5，也不要排成 v2.5 future work。

我希望它直接納入目前 v2.4-rc6，並在 RC6 publish 前完成。

原因是這不是新的 content expansion，而是目前既有：
order → table → customer → dialogue → character
之間缺少的基本 UX connection。

目前遊戲已經有很多 named characters / regulars / story characters，
但實際遊玩時我幾乎只穩定認得 Jill 和 Dylan。

如果先進 P5 再增加更多 staff / family / character stories，
只會讓這個 identity disconnect 更嚴重。

因此 RC6 release order 請調整為：

1. Finish current RC6 Staff Room / PDR / Second Floor polish
2. Finish Customer Identity & Spatial Linking Pass
3. Targeted mobile QA for this pass
4. Existing RC6 release QA / full regression
5. Publish v2.4-rc6
6. Then continue P5 as already planned

For RC6, prioritize the smallest complete version:

MUST HAVE
- tap order / T-number → switch to correct room + focus/highlight that table
- tap occupied table → show table number + party/customer identity
- tap visible customer → show name + table number where applicable
- tap dialogue speaker/name → locate/focus/highlight the actual speaker
- all of the above must work across rooms
- named characters must use their real canonical identity, not generic labels

NICE TO HAVE IN RC6 ONLY IF CHEAP / SAFE
- stronger visual recognition cues for recurring named characters
- improved sprite/outfit resemblance to portrait
- additional identity polish

Do NOT delay RC6 by building a large NPC identity framework or redrawing the whole cast.

The immediate goal is extremely concrete:

When I see a name, I can find the person.
When I see a person, I can know the name.

I want this in the RC6 build I play next, not in a later roadmap version.

Please treat this as an RC6 release requirement.

REPORT ≠ STOP.
