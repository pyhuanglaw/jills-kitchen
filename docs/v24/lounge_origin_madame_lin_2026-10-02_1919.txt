請先 audit 現有 code / story data / save schema / Lounge unlock / wine progression / character knowledge / mature-save migration。

==================================================
0. 核心世界觀
==================================================

Jill’s Kitchen 原始店面與 The Lounge 不是同一個店面。

原始 Jill’s Kitchen 一樓包含：
- Main Hall
- Side Hall
- Kitchen
- Jill + Dylan 私人房間

The Lounge 位於 Jill’s Kitchen「隔壁的獨立店面」。

它原本是一間已經營業很多年的 neighborhood bar，
老闆就是現有角色 Madame Lin。

【HARD CANON】

Jill’s Kitchen 與隔壁酒吧：
- 各自有獨立對客入口
- 中間牆不能打通
- 不存在 Main Hall → Lounge 的直接門
- 玩家切換時可以使用簡單 UI / transition
- 世界觀上是走出本店，再進隔壁

但兩邊後場位置使 Jill’s Kitchen 的 Kitchen 可以支援 Lounge。

因此：
- 保留現有 shared Kitchen production logic
- Lounge 不需要建立第二套完整 Kitchen
- Lounge food 可以由 Jill’s Kitchen Kitchen 製作／支援
- 不需要把後場 service route 做成複雜 walking simulation

「前場不相連」與「共用 Kitchen production」並不衝突。

這個條件後來也會成為 Madame Lin 認為 Jill 接手具有實際可行性的理由之一。

==================================================
1. Madame Lin 的既有身分
==================================================

Madame Lin 不是為 Lounge origin 新增的 NPC。

她本來就是既有 special regular。

現在補充她一直存在的背景：

Madame Lin 是 Jill’s Kitchen 隔壁酒吧的老闆，
已經經營很多年。

她住／生活在這個 neighborhood，
與這個地方有長期關係。

她不是：
- 神秘富豪
- 房東
- 投資人
- 商業導師
- 悲情前店主

她就是一個經營隔壁小酒吧很多年的成熟女性。

她與 Jill 的關係從「鄰居店家」自然發展成 regular。

==================================================

==================================================

在 Day 1 正式開店以前：

Jill 與 Dylan 已經一起整理／準備／裝修 Jill’s Kitchen。

因為 Madame Lin 的酒吧就在隔壁，
她在這段期間自然認識兩人。

因此遊戲開始時：

Madame Lin 已經知道：
Dylan = Jill 的丈夫。

她不需要透過後來的 reveal 才知道。

【重要】

這不代表其他 NPC 也知道。

不要建立 global knowledge sync。

角色知道資訊必須依實際經歷決定。

初期大致為：

- Jill：當然知道
- Madame Lin：pre-game 裝修期就知道
- Evan：尚未認識 Dylan / 尚不知道
- Restaurant staff / regulars：依原有 story progression，未必知道

因此原本 Jill’s Kitchen 餐廳內的：

「Dylan 原來是 Jill 老公」

reveal story 可以保留。

Madame Lin 早就知道，不會破壞這條線。

3. STORY 1：《隔壁》
Day 1 / very early
==================================================

Jill’s Kitchen 正式開店。

Madame Lin 帶一個簡單、自然的開店小禮物來。

目的：
在遊戲一開始就讓玩家知道：

1. Madame Lin 是隔壁酒吧老闆
2. 她與 Jill 已經認識
3. 她是鄰居
4. 兩家店在物理上相鄰
5. 她對 Jill 開店是友善、自然的態度

不要把這幕寫成大量 exposition。

參考：
Madame Lin：「終於開了。」
Jill：「嗯。」
Madame Lin：「恭喜。」
Jill：「謝謝。」
Madame Lin把禮物遞給她。
Jill：「妳還帶東西來。」
Madame Lin：「開店哪有空手來的。」
Jill：「妳不是就在隔壁。」
Madame Lin：「隔壁更不能空手。」

即可。

禮物可以是：
- 小植物
- 小型實用物
- 簡單開店禮

不要豪華。
不要象徵意味過重。
不要讓角色解釋禮物代表什麼。

如果 Dylan 在場，
Madame Lin 可以自然與他打招呼，
因為兩人在裝修期間已經見過。

但不要在此特別向玩家宣布：
「這是 Jill 的老公。」

保留餐廳內未來 Dylan 身分 reveal 的空間。

不要新增：

21. STAFF ARCHITECTURE — 同次實作
==================================================

這次請同時正式修正 staff capacity architecture。

Restaurant staff 不再使用一個 generic shared pool。

必須拆成三個獨立 employment categories：

1. Chef / 廚師
2. Waiter / 服務員
3. Cleaner / 清潔員

三者各自獨立：

- hiring category
- capacity
- occupied slots
- roster accounting
- expansion bonus
- unlock / upgrade effects

例如：

+1 Chef slot
只能聘 Chef。

不能拿去聘 Waiter / Cleaner。

+1 Waiter slot
不能被 Chef / Cleaner 使用。

+1 Cleaner slot
不能被 Chef / Waiter 使用。

未來所有 staff-capacity upgrades，
都必須明確指定增加哪一個職種。

不要再出現：

Restaurant Staff +2

但實際上三種職業可以任意共用的 generic pool。

24. Dialogue / writing rules
==================================================

整條故事請保持：

短。
生活化。
角色不把主題說破。

避免：

「這裡對我來說像家。」
「這間店承載了很多回憶。」
「妳一定可以讓它變得更好。」
「這是新的開始。」
「我相信妳。」
「我們一起努力。」

「我終於可以放心退休了。」
「這個地方會延續下去。」
「我們不只是同事。」

不要讓角色知道劇本。

不要讓每個角色都正確理解所有人的想法。

Ken 只是在意喝酒。
Dylan 只是聽到老婆有點想接，所以默默開始看書。

Jill 最後自己決定。

==================================================

不要把這條線做成：

玩家體驗應該是：

→ Ken 問 Jill 為什麼自己不賣酒
→ Jill 慢慢發展 pairing wine
→ 原本穩定存在的 Madame Lin 某天說要退休
→ Ken 擔心自己熟悉的地方要沒了
→ Jill 開始想到「要不要接」
→ 回家跟 Dylan 談
→ Dylan 幾天後默默看 bar design book
→ Jill 去看店
→ 發現 shared Kitchen 讓事情實際可行
→ 認識原 bartender Evan，知道他願意留下
→ Jill 自己做決定
→ Dylan 陪 Jill 去簽約
→ Evan 第一次正式認識 Dylan
→ 改裝
→ The Lounge 出現
→ Madame Lin 退休後偶爾回來喝
→ Lounge 又開始產生 Ken / Evan / 沈晴 / 阿拓 / 予安 / Dylan 的新故事

核心：

NEED / LIFE PATTERN FIRST
→ OPPORTUNITY LATER
→ SPACE CHANGES
→ NEW LIFE HAPPENS INSIDE THE SPACE

不是：
BUILDING UNLOCK → CONTENT SPAWNS。
