正式 Cooking Workflow Canon

全系統只有五種玩家可理解的工作區：

* PREP = 備料／冷盤
* HOT = 煎、炒、煮、燉、炸
* OVEN = 烤製
* DRINK = 飲料製作
* PLATING = 裝盤／最後完成，原則上整合現有 Pass 廚房側

其中：

等待不是 Step。

翻面不是 Step。

起鍋不是 Step。

瀝乾不是 Step。

加高湯不是 Step。

撒鹽、蔥花、羅勒、糖粉、醬汁、garnish 不應單獨成 Step。

它們都是該工作區內部的 character animation / food animation / finishing animation。

新增 HARD RULE：玩家永遠不需要背下一步

Cooking System 不可以建立在玩家記住食譜流程的前提上。

即使玩家已經玩到 Day 100、做過這道菜 50 次，系統仍然必須在每一個 workflow step 完成後，清楚告訴玩家：

「這道菜下一步去哪裡。」

這不是只在新手期出現的 Tutorial。

這是 Cooking Gameplay 永久存在的核心 UI。

⸻

1. 每一道正在料理的菜，永遠顯示完整 Workflow

例如牛排：

備料 → 熱區 → 裝盤

如果目前正在備料：

● 備料 → ○ 熱區 → ○ 裝盤

備料完成：

✓ 備料 → ● 熱區 → ○ 裝盤

熱區完成：

✓ 備料 → ✓ 熱區 → ● 裝盤

不要只顯示：

「牛排 67%」

因為百分比不能告訴玩家：

現在要去哪裡。

⸻

2. Step 完成時，立即告訴玩家下一步

例如：

玩家正在做：

炙烤肋眼牛排

PREP 完成的瞬間：

料理本身／ticket 應該自然更新成：

下一步：熱區

同時：

從目前料理位置到合法 HOT station，出現清楚但漂亮的 directional cue。

玩家不需要打開說明。

不需要點 recipe book。

不需要回想食譜。

遊戲直接回答：

下一步在那裡。

⸻

3. 要有空間上的箭頭／方向提示

這是必要功能。

但是不要做成廉價手機遊戲的：

* 巨大黃色箭頭
* 不停跳動
* 閃爍紅框
* 全畫面教學遮罩
* 「請點擊這裡！！！」

應該融入原本 Jill’s Kitchen 的視覺。

例如：

料理完成 PREP 後：

料理 → HOT

可以從料理所在位置出現一條短暫、柔和的 directional trail / arrow。

箭頭指向：

實際可以使用的 HOT station。

同時合法 HOT station 有：

* subtle warm outline
* 很輕的呼吸亮度
* hover / touch feedback

所以玩家即使完全沒看文字，也知道：

喔，這盤現在要拿去那邊。

⸻

4. 指的是「可用的實際位置」，不是抽象 station icon

例如牛排下一步是 HOT。

不要只在 UI 上顯示：

🔥 HOT

而是要讓玩家知道：

廚房裡哪一個地方就是 HOT。

如果現在有三個 burner：

箭頭／highlight 可以指向：

* 可使用的 burner
* 或 HOT zone 整體，再讓玩家選 burner

如果其中兩個已經占用：

優先 cue：

目前真的可以使用的那一個。

這會讓教學與 station capacity 本身整合。

⸻

5. 如果下一個 Station 暫時滿了，也要說清楚

例如：

牛排完成 PREP。

下一步 HOT。

但是所有 burner 都滿了。

不要讓箭頭消失，讓玩家以為自己做錯。

應顯示：

下一步：熱區 · 目前忙碌

料理進入安全等待。

HOT station 仍可以有較弱的 cue，讓玩家知道：

我要去那裡，只是現在沒位置。

一有 burner 空出來：

cue 自然變成：

可進行

不要用紅色 FAIL / ERROR。

這只是廚房忙，不是玩家犯錯。

⸻

6. 料理完成一個 Step 後，提示應該立即接續

不要：

Step 完成
→ 所有 UI 消失
→ 玩家自己找下一步
→ 點 ticket
→ 才知道去哪

正確節奏：

Step 完成
→ food visual 進 ready-for-next-step state
→ workflow 自動更新
→ 顯示「下一步：___」
→ directional cue 指向下一 station
→ 玩家可以立刻操作

整個過程不能有認知斷裂。

⸻

7. 但提示不能逼玩家立刻做

這點同樣重要。

箭頭的意思是：

「下一步在這裡。」

不是：

「現在立刻給我按這裡。」

玩家可以：

* 先處理另一鍋
* 去看另一張 ticket
* 讓員工接手
* 去主廳
* 看一下貓
* 過一會再回來

料理安全等待。

提示仍然存在，但不要：

* 越閃越快
* 變紅
* 倒數
* 播警告音
* 製造焦慮

⸻

8. 員工接手時，同一套提示仍成立

例如：

牛排：

✓ PREP → ● HOT → ○ PLATING

玩家看到下一步 HOT。

如果這時阿德自己接手：

workflow 變成：

✓ PREP → ● HOT（阿德） → ○ PLATING

HOT station 的 directional cue 可以自然淡出，因為這件工作已經有人處理。

等阿德完成：

立刻變成：

✓ PREP → ✓ HOT → ● PLATING

並指向 Pass / PLATING。

如果玩家不碰：

合適員工仍可繼續接 PLATING。

所以 guidance system 與 staff system 必須共用同一個 workflow state。

不要寫兩套 UI。

⸻

9. Batch 也使用完全相同的提示

例如：

黃金蛋炒飯 ×3

顯示：

● HOT → ○ PLATING

HOT 完成：

黃金蛋炒飯 ×3
✓ HOT → ● PLATING

並指向 PLATING / Pass。

不要因為 ×3 就出現三支箭頭、三張提示、三個相同 workflow。

Batch 是一個 work node。

⸻

10. Ticket 本身就是永久的小型 Recipe Guide

每張 active cooking ticket 至少要讓玩家看到：

料理名稱

份數

完整 workflow

目前所在 step

下一步

目前由誰處理（如果有人）

例如：

炙烤肋眼牛排 ×2

✓ 備料 → ● 熱區 → ○ 裝盤

阿德正在處理

或：

炙烤肋眼牛排 ×2

✓ 備料 → ● 熱區 → ○ 裝盤

下一步：熱區
目前忙碌

不要塞：

* 秒數
* 大量 stats
* recipe text
* ingredient checklist
* quality meter

玩家最需要知道的只有：

它現在在哪、下一步去哪、有人在做嗎。

⸻

11. 選中 Ticket 時，Guidance 加強

平常不要讓整個廚房到處都是箭頭。

否則同時五道菜會變成交通號誌。

分兩層：

Passive Guidance

沒有選中料理時：

ticket 上永遠看得到 workflow 與 next step。

料理本身可以有非常輕的 ready indicator。

⸻

Focused Guidance

玩家點選某一道 ticket / batch：

立刻：

1. 該料理視覺被輕微 highlight
2. workflow 更清楚
3. 顯示「下一步：HOT」
4. 廚房中的合法 HOT station highlight
5. directional arrow / trail 指向該區
6. 不合法 station 不需要反應

因此：

箭頭主要服務「目前選中的料理」。

不要五道菜同時五支箭頭亂飛。

⸻

12. 第一次使用某 Station 可以多一點文字，但之後仍保留基本提示

例如玩家第一次完成炒飯 HOT：

可以出現一次比較完整的小提示：

炒好了。接下來送到出餐口裝盤。

＋ directional arrow → Pass。

但之後即使不再出完整句子：

仍然永遠有：

✓ 熱區 → ● 裝盤

下一步：裝盤

＋選中時的 directional cue。

也就是：

Tutorial 文案可以逐漸退場。

Gameplay guidance 永遠不能退場。

⸻

13. 不要用「玩家已經學會了」作為移除提示的理由

這是 HARD RULE。

不要做：

Day 1–3 有箭頭
Day 4 後沒有。

不要做：

一道菜做過 5 次後取消 workflow。

不要做：

Mastery LV3 後隱藏提示。

不要做：

「進階玩家應該記得」。

Jill’s Kitchen 的料理樂趣不是考記憶。

就算玩家半年沒開遊戲，回來第一盤牛排仍然應該一眼知道：

PREP → HOT → PLATING

而且做完 PREP 後，遊戲直接指出 HOT 在哪裡。

⸻

14. Guidance 也是降低難度的核心機制

這一點請不要把它當 polish。

它直接決定 Cooking System 難不難。

我們允許同時存在 3–6 個 meaningful work nodes，是因為玩家不用把這些資訊記在腦中。

遊戲替玩家保存 external memory：

炒飯 → 等裝盤

牛排 → 正在熱區

鮭魚 → 下一步烤箱

沙拉 → 正在備料

玩家真正需要思考的是：

「我現在先處理哪一個？」

而不是：

「靠，我忘記鮭魚下一步要去哪。」

前者是我們要的 orchestration。

後者是無聊的 cognitive load。

⸻

15. Prototype Acceptance 加入 Guidance Test

黃金蛋炒飯 prototype：

HOT → PLATING

必須驗證完整 guidance：

開始時：

黃金蛋炒飯 ×1
● 熱區 → ○ 裝盤

選中後：
→ 合法 burner cue

HOT 完成：

黃金蛋炒飯 ×1
✓ 熱區 → ● 裝盤

立即：
→ 顯示「下一步：裝盤」
→ directional cue 指向 Pass / plating area

玩家不操作：
→ 不失敗
→ cue 保留
→ 員工可以接手

員工接手：
→ UI 顯示員工正在處理
→ cue 自然降低

完成：
✓ 熱區 → ✓ 裝盤

然後正常進 serving flow。

⸻

16. Concurrent Test 特別檢查「不用記」

之後測 4–6 個 concurrent work nodes 時：

請故意讓它們處於不同階段，例如：

炒飯 ×3
✓ HOT → ● PLATING

牛排 ×2
✓ PREP → ● HOT → ○ PLATING

鮭魚 ×1
✓ PREP → ● OVEN → ○ PLATING

沙拉 ×2
● PREP → ○ PLATING

測試者不看任何 recipe book。

只看目前遊戲畫面。

Acceptance：

任何一道料理被點選後，2 秒內應該可以知道它下一步去哪。

如果需要：

* 回想
* 猜
* 打開說明
* 點很多層 UI
* 記住 recipe

則 Guidance UX 不合格。

⸻

Cooking System 的 UI 原則最後濃縮成一句：

遊戲負責記住流程，玩家只負責做決定。

玩家永遠知道：

這道菜現在在哪裡。

下一步要去哪裡。

那個地方在廚房哪裡。

但是：

什麼時候送過去、要不要自己做、要不要交給員工、哪一道先處理——才是玩家玩的部分。
