## 一句話

一道菜（或同一道菜的一批）是一個「工作」（work node）。它照自己的流程（例如 熱區 → 裝盤）一站一站走；每一站是廚房裡本來就有的位置，
有容量限制；Jill 和廚師用同一套規則接手。

## 名詞

| 遊戲裡的說法 | 程式 | 廚房裡的實際位置 |
|---|---|---|
| 備料 PREP | `prep` | 冷盤台的砧板（現有 `prep` slots） |
| 熱區 HOT | `hot` | 爐台的爐口（現有 `stove` slots） |
| 烤箱 OVEN | `oven` | 烤箱（現有 `oven` slots） |
| 飲料 DRINK | `drink` | 咖啡機（現有 `bar` slots） |
| 披薩烤爐 | `pizza` | 披薩烤爐（現有 `pizza` slot，固定 1） |
| 裝盤 PLATING | `plate` | 出菜口廚房側（新的 `pass` slots，用出菜口現有的盤位） |
| 出杯 SERVE | `serve` | 飲料放上出菜口取餐側；不占容量 |

水槽、冰箱、冷藏室不是流程的一站；角色可以在動畫裡走過去。

## 工作（work node）

```
{ id, d: 菜, n: 份數, its: [ticket items], si: 第幾站,
  st: 'wait' | 'fetch' | 'go' | 'work' | 'cook' | 'ready',
  slot: 占用的位置, to: 要去的位置, who: 'jill' | 廚師 id | null, act / pas: 這一站剩下的手作／自己煮的時間,
  sc: 每一站的分數, ck: 碰過這道菜的廚師 }
```

- `wait`：還沒開始這一站，在等位置或等人。
- `fetch`：有人來拿上一站做好的菜（例如從爐上端去出菜口）。
- `go`：已經有人接，人在走過去（下一站的位置先保留）。
- `work`：人在那一站做（手作的部分）。
- `cook`：自己在煮（爐上、烤箱裡），不需要人站著。
- `ready`：這一站做完了，菜留在原地，等送去下一站。不會壞、不會焦，也不會變差。

一個工作從開始做到被送去下一站，一直占著那一站的一個位置。一批（例如 炒飯 ×3）只占一個位置。

## 畫面：沿用原本的廚房

- 沒有新的格子、按鈕或 HUD。每一站就是原本的位置：爐口、烤箱、咖啡機、冷盤台的砧板、出菜口上的盤位。
- **每一站畫什麼**，從那道菜原本的食譜讀出來（`wfLook`）：
  - 備料：如果那道菜在下鍋前本來就有刀工（鴨胸劃刀、舒芙蕾打蛋白、切蔬菜、切菜、開生蠔、捏可樂餅），就是原本的砧板和刀工；
    沒有的話，是那道菜自己的容器，食材一樣一樣放上去；要下鍋的菜（漢堡、牛排、海鮮麵）放在盤子上備好。
  - 熱區：原本的鍋，裡面是下鍋前就放的食材，炒的時候會拋鍋、煮的時候冒煙，熟度跟著進度變。
  - 烤箱、披薩烤爐：放進去以後在烤箱裡，原本的烤色跟著進度變。
  - 飲料：在咖啡機下，倒奶、倒氣泡水是原本的倒入畫面。
  - 裝盤：出菜口的盤位上，原本的料理圖，做完的瞬間撒上原本的最後裝飾。
- 一批會在鍋旁邊小小寫 ×2、×3。
- Jill 會走到她被派去的位置做事（規格：「Jill 自己走過去」）；廚師也一樣。

## 玩家怎麼操作、怎麼知道下一步（引導）

- 訂單條上每道菜下面有一行小標記，例如 `熱›裝`，現在在哪一站用粗體。
- 點訂單上的菜：選中它，畫面切到廚房，下面出現一張小卡：菜名（一批寫 ×3）、整個流程（✓ 做完的、● 現在、○ 還沒）、下一步。
  它可以去的位置會暖暖地亮起來，從菜指過去一條慢慢流動的虛線箭頭。
- 點亮起來的位置：Jill 走過去做。沒有選菜的時候，直接點一個空的位置，Jill 會接等最久、下一步是那裡的菜。
- 下一站滿了：卡片寫「下一步：熱區 · 目前忙碌」，位置只淡淡地亮，不會有錯誤、紅字或警告。
- 做好的菜在原地等，旁邊一個小小的 ✓；等多久都不會壞、不會焦、分數不會掉。
- 沒有計時器、百分比、分數；有經驗的玩家也一樣看得到這些（不會關掉）。
- 第一天的教學三句改成新的做法（點訂單上的炒飯 → 點亮起來的爐口 → 好了點出菜口）。

## 廚師（M7）

**程式**：`chefProf(m, 位置)` 給 0–3：3＝專長、2＝熟練、1＝會做、0＝不會。飲料不在廚師的專長表裡，每位廚師都會（熟練）。
派工（`wfStaff`）每 0.2 秒看一次：每位有空的廚師，跟每個等人接的步驟配對打分（專長 × 100＋等了多久＋本來就排在那一站的加一點），
分數高的先配；「會做」（★）的人對剛出現的工作會先等 6 秒，讓更適合的人先接（規格 §20：★ 不太主動跨區接）。

## 改過的測試（防災條款 10）

每一條都寫：原本驗證什麼、為什麼不再成立、改成什麼。測試本身的 docstring 也寫了。

1. **`cooking_every_recipe`**：原本——每道菜用舊的工作站、完美操作，都是 Perfect。不再成立——表上的菜沒有舊的工作站了
   （`startCook` 不接），全部回報 NO_SLOT。改成——還在舊做法的兩種披薩照舊驗證；表上的菜由 `cooking_every_family_goes_its_own_way` 驗證。
2. **`cooking_flow_families`**：原本——舊的操作形狀（每道 2–5 次操作、翻面／起鍋抓時機、燉煮長等待、冷盤快、飲料量表），
   以及漢堡晚一點翻面會被原諒、忘了會焦。不再成立——規格：等待、翻面、瀝乾都不是步驟，沒有時機，不會焦。改成——它點名的菜
   都是使用者表上的流程；兩種舊做法的披薩保留舊規則（2–5 次、醬的量表和烤、Perfect），原諒／燒焦改在披薩的烤上驗證。
3. **`kitchen_staff_ladder`**：原本——LV3 以上的廚師才會接手 Jill 開始做的菜（炒飯、海鮮麵的舊工作站）。不再成立——新廚房沒有
   「做到一半換人」，交接在兩站之間，誰會做下一站誰接。改成——等級規則照舊（LV1 不碰海鮮麵這種 LV3 的菜，LV3 會接）；
   舊的接手規則在舊做法的披薩上驗證。
4. **`waiter_serves_ready_food`**：原本——LV2 服務生會把做好的菜端上桌。不再成立——這個測試自己的玩家只會舊做法，菜都沒做好。
   改成——它的玩家也會用新廚房（跟標準測試玩家一樣），期待不變。

## 技術衝突（程式現況跟規格不一樣的地方，沒有自己改）

1. **第 1–3 天沒有冷盤台**：規格的備料前期是 1，遊戲第 4 天才有冷盤台。需要備料的菜（漢堡等）在沒有冷盤台時點不了，菜單上寫
   「缺少冷盤台，客人不會點」（跟以前沒有烤箱時一樣）。只影響第 2 天晚上就研發漢堡的玩家的第 3 天。
2. **熱區前期**：規格前期 2，遊戲第 1–2 天只有 1 口爐（第 3 天第二口到貨）。沒改，改了會動到前期節奏。
3. **熱區上限**：規格最多 6，現在爐灶 LV5（4）＋廚房擴建（+2）＋Bar 小廚（+1）＝7。Bar 小廚的說明寫「專做 Lounge 的小食，
   不是第二個廚房」。沒改（見決定事項第 5 條）。
4. **備料第三個位置**：規格後期 3，現在最多 2。要加在廚房擴建或後場工程的畫面裡（規格：要看得到），還沒做。
5. **巴斯克乳酪蛋糕**：舊版在冷盤台（「烘烤定型」是冷盤台上的等待），使用者的表是 備料 → 烤箱 → 裝盤。照表做，所以沒有烤箱時點不了。
