# Version 16：做菜流程、Dylan 的戲、等候長椅、備份存檔

V15（`git tag v15-life`）是這一版的回歸基準。沙發、Jill 的晚上、五隻貓的沙發行為、Dylan 的隱藏階段與揭露機制都沒有重新設計；這份文件列出改了什麼、哪些是規則自己長出來的、Dylan 現在怎麼運作、測試怎麼變、以及做的時候撞到的舊設計。

## 1. 做菜流程（Dave the Diver 式）

**改了什麼**

- 連點步驟 `sT` 整個拿掉。切菜、打發蛋白、劃刀、拌炒這些手工變成 `sK`（work）：玩家開始後 Jill 自己做完，面板顯示「Jill 正在切菜…可以先去做別的」並自動收起。翻炒、燉煮用 `sW(…, 'stir')`，鍋裡會動、Jill 在出餐口拿著鏟子。
- 24 道菜全部重寫成五種家族，一道普通菜 2–5 次操作（測試會數）：
  - 煎：放料 → 等 → 翻面 → 等 → 起鍋（漢堡、牛排、鴨胸、招牌菜）
  - 燉煮：快速備料 → 長時間等 → 回來加一次 → 完成（南瓜濃湯、松露燉飯）
  - 冷盤：幾秒手工 → 擺盤 → 淋醬（沙拉、生火腿沙拉、提拉米蘇、布丁）
  - 快炒：照順序放料 → 短暫翻炒 → 一次調味（炒飯、番茄麵、海鮮麵）
  - 烤箱：備料 → 長時間等 → 出爐（薯條、烤蔬菜、烤雞、鮭魚、舒芙蕾）
  - 飲料：長按量表，完全沒動。
- 上桌時自動擺上的配料（蔥花、羅勒、檸檬…）搬到 `fin`，不再是一個步驟。
- 寬容：抓時機的 PERFECT 區 ±w、GOOD 區 ±(w+.12)，超過 1.0 是「有點過」只扣分，超過 1.22 才焦；等待步驟超時（`over`）才扣分，燉煮類 `over=0` 永遠不扣。鍋子真的被忘記（1.5）才會燒起來。
- 面板在 Jill 自己做事時 0.9 秒後自動收起（原本等待步驟就會收，只是更快看不清楚字）。
- 員工：
  - 廚師 `chefCan`：只做 Jill 已做過的菜、難度 ≤ min(3, 等級)。LV1 簡單菜、LV2 一般菜、LV3 起接手 Jill 已經開始的菜（`chefHandles`）。招牌菜與每道菜的第一份永遠是 Jill 的。
  - 服務生 LV2（帶位＋點餐）會把出餐口做好的菜端到桌上（新任務 `serve`，盤子畫在手上）。
- 教學（`COACH`）、遊戲說明的「做菜」「帶位」段落、菜單卡上的步驟文字跟著改。

**數據**（12 天 × 完美機器人，`study16.py`）：每道菜操作次數 炒飯 5、咖啡 2、義大利麵 2、沙拉 4；同時有兩鍋以上在做的時間佔營業時間 15–20%；店裡完全沒人、沒事做的時間 1%；玩家「當下沒有東西必須馬上按」的時間約 70%——等待是資源，空檔是拿來帶位、送餐、看貓的。

## 2. 生活系統

沒有改任何 V15 規則或機率。只補了兩個 V15 留下的視覺問題（見第 6 節），以及貓多了一個可以去的地方（長椅，權重很小，見第 4 節）。`jill_evening_life`、`cats_use_sofa_by_personality`、`sofa_geometry`、`dylan_hidden_reveal` 都沒改內容，全部通過。

## 3. Dylan

前提從第一天就是：兩個人早就結婚了，被騙的是玩家；Jill 知道，配合演。

- **付錢**：跟所有人一樣付款。小費 ×1.35（`collect`），點飲料機率 0.7。他平均三天來一次，30 天模擬裡他的營收＋小費約占 3–4%，而且來不來是排程決定的，玩家沒有辦法讓他多來。
- **收拾自己的桌子**：結帳後如果不留下（V15 的 `dylanStays()` 為否），他把盤子端到出餐口再走出門，桌子直接乾淨（`g.bus`，畫面上手裡有盤子）。留下的晚上照 V15 走。這是習慣，不是工作：沒有薪水、沒有任務、`ROLES`／`CREW_NAMES`／`S.crew` 裡永遠沒有他（測試守著）。
- **追求戲**（`DYLAN_ACT`）：Jill 空下來時，一次來店最多說一句話，其中一半是追求台詞，Jill 回一句或不理。揭露前：「老闆娘，今天有空嗎？」「沒有。」／「老闆娘，妳有男朋友嗎？」「先吃飯。」／「我下次帶花來。」「帶錢來就好。」／「老闆娘，妳綁馬尾很好看。」（Jill 看了他一眼，沒有回答。）揭露後同一齣戲繼續，只是變成兩個人的老梗：「老闆娘，明天有空嗎？」「不行，我老公會生氣。」「那確實滿麻煩的。」／「可以留個電話嗎？」「你不是有嗎？」「再要一次也不行喔？」沙發上偶爾也演一段（每次聊天 25%）。
- **揭露**：V15 的機制原封不動（Jill 在沙發、他坐到她身邊、2.5 秒後一張照片「Dylan — Jill 的先生」），只多了兩個小泡泡：Jill「老公。」Dylan「嗯。」（電視開著時是「老公，遙控器。」「喔。」）。沒有橫幅、愛心、任務、數值。
- **等位子**：客滿時他跟大家一樣坐長椅，先來先坐，沒有插隊；只是耐心比較好（V15 的 ×0.5 沒動）。

**什麼是規則長出來的**：他哪天來、坐哪張桌子、什麼時候看 Jill 一眼、說哪句話、Jill 回不回、留不留下、在沙發上坐哪、貓擠不擠在中間、揭露發生在第幾天，全部是 V15/V16 規則＋當晚狀態＋骰子決定的。沒有一段是寫死的劇本。

## 4. 等候長椅

- 門口下方一張木頭長椅（`BENCH`，跟椅子同一套木色與裝潢等級），三個位子＋旁邊兩個站位。
- 流程：進門 → 有合適空桌就自己走過去坐 → 沒有就去長椅坐（3 人以上站在旁邊）→ 坐著等，2–4 秒看一次有沒有空桌，先來先起身走過去。沒有瞬移，走的是原本的移動系統。玩家點客人或點空桌可以馬上帶位，服務生的帶位任務也還在。
- 等待時的小動作：發呆、看手機、看店裡、看附近的貓、兩個人聊天。純視覺。坐著等的人耐心消耗 ×0.7。
- 貓：`catDecide` 多了 `bench`（寶寶 0.5、包包 0.15、其他 0.25），一次一隻、至少留兩個空位、有人站著等時不去。客人挑位子時避開貓的那一格，貓走了站著的人自己坐過去。沒有強制互動，沒有死結（測試 `waiting_bench`）。
- 位子全滿、門口也滿了：新來的客人「看到客滿，失望地走了」（原本就有的機制）。沒有大排長龍。
- 人氣指標是自然長出來的：前期桌子夠，長椅通常是空的；後期客人多，就會有人坐在那裡等。

## 5. 本機存檔備份

- 設定畫面：「**本機存檔** · 已自動儲存（上次存檔 時間）」＋說明「遊戲進度會自動儲存在目前使用的瀏覽器中。清除網站資料、換瀏覽器或換裝置時，進度不會自動帶過去。」
- 「備份存檔」：一個檔案 `JillsKitchen_Save_YYYY-MM-DD_HHMM_DayN.json`（外殼 `{app:'jills-kitchen',kind:'save',v,exported,save}`）。
- 「讀取存檔」：選檔案 → `parseSave`（解析 → 是不是我們的存檔 → 版本 → migration → 預設值 → 合理性）→ 顯示「讀取這個備份？DAY n · $m，目前的進度會被取代」→ 玩家確認才換掉 `S`。壞檔案、不相干的檔案、比較新的版本都會被拒絕，一句 zh-TW 提示，目前的進度不動。
- 瀏覽器自己的那份存檔和備份檔走同一條 `parseSave` 管線。舊存檔（`tests/fixtures/*.json`）從檔案讀進來也一樣會補欄位。
- 原本的 SAVE／LOAD／RESET GAME 改成「存檔」「回到上次存檔」「重置遊戲」。

## 6. 做的時候撞到的舊設計（都已處理）

1. **員工待命點在沙發上**：V15 沙發變成常設後，服務生 (110,136)、清潔 (300,136) 的待命點剛好落在沙發座墊上。改到門邊 (84,150) 與右側 (362,190)。
2. **舊的排隊位置 QPOS k≥3 在 x=92**：也是沙發上。長椅取代了整個 QPOS。
3. **教學第一句與「帶位」浮標**：客人會自己入座後，「點門口的客人，帶他們入座」不再成立；文字改掉，浮標拿掉，點擊帶位保留為加速手段。
4. **`sT` 拿掉後的文字**：遊戲說明的「做菜」段落、菜單卡的步驟摘要、第 4 句教學重寫。設備故障事件的「連點修理」不是料理，保留。
5. **個性指紋測試**：貓多了 `bench` 選項，決策權重雜湊必然改變；確認「包包最會睡」的獨立檢查仍成立後重新錄製。
6. **LOAD 的意思**：原本的 LOAD 是「重新讀瀏覽器裡那份」，跟新的「讀取存檔（檔案）」會混淆，改名「回到上次存檔」。
7. **`long_play`／`touch_controls` 測試假設**：觸控測試原本假設客人會站在門口等人點；改成先把桌子弄髒讓客人坐長椅，再點。
