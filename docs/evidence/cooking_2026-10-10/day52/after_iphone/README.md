## 原因：測試的天氣不在測試的種子控制裡

- 每天的天氣是在「下一天」按下去的那一刻（`planToday`）用亂數抽的。測試是在**那之後**才把當天的亂數設成自己的種子，所以抽天氣
  用的是「前一晚營業剩下的亂數」。
- 前一晚只要多抽或少抽一個亂數（例如廚師多做一步、Jill 去摸貓），之後每一天的天氣就整串換掉。同一個種子 7500：兩個版本從第
  54 天起天氣就不一樣（`wx_diag.py`，`wx_8ded2e2_7500.txt`、`wx_6bf5002_7500.txt`；7600 也一樣）。
- 所以 14 個種子在兩個版本上，其實是兩組不同的天氣。《去怡君家》要等雨，這次新版本剛好抽到乾的日子。
- 遊戲本身的天氣規則（`planToday` 的權重、前一天下雨下一天比較容易下、傍晚突然下雨 `rainstart`）在這兩個版本之間一行都沒改
  （`git diff 8298e18 6bf5002 -- js/game.js` 和 `git diff 8ded2e2 6bf5002 -- js/game.js` 都沒有碰到 `planToday`、`wpick`、`wxPrev`、
  `rainstart`、`planIncidents`、`v24Wx`、`rainedWithin`、`wallRain`、《去怡君家》的條件）。

## 處理

1. **修測試的缺陷**（不是換種子了事）：測試裡每天早上抽天氣也用自己的種子（`planToday` 外面包一層，抽之前把亂數設成
   底數＋500000＋第幾天）。這樣同一個種子底數，在每一個版本上都是同一串天氣；以後改廚房、改員工，不會再把天氣整串換掉。
   原測試不合理的具體原因：它要量的是故事的節奏，可是兩拍故事等的天氣不在它的控制裡，量到的大半是天氣的運氣。
2. **種子照同一條事先寫好的規則重選**：14 個種子裡，在 main 和 6bf5002 上都達到每一個目標的是 7600、7800、8000、8100，號碼最小的
   是 **7600**（兩個版本的日子一模一樣：認識 53、鑰匙 61、牆 63、調解 80）。
3. **測試的每一項檢查、每一個門檻都沒改。**
4. 證明改過的測試還抓得到節奏變慢（`mutants.txt`）：6bf5002 的遊戲通過、main（8298e18）的遊戲通過；三個做壞的版本都失敗——
   怡君搬家晚兩天（鑰匙第 63 天）、調解晚六天（第 86 天）、二樓跟著牆開（沒等 Lounge）。

## 照實記下

- 這個測試以前已經因為「時間線移動」換過很多次種子（測試的註解有每一次的紀錄）。天氣不受控制是其中一部分原因；這次修掉以後，
  時間線還是會因為每晚的客人、走位而移動（例如 Sophie 和 Mia 坐不坐得到同一個房間），只是不會再因為天氣整串換掉。
- main 本身在固定天氣下也只有一半的種子達到每一個目標（7／14），跟之前量到的一樣（8／14）：使用者的目標本來就很貼著現在的
  節奏（Release Gate 2026-10-10「十」）。
