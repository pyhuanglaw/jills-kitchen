# 開店前畫面的小按鈕（Audit WS2-15，2026-10-13 還是這樣）

**量到的**（使用者第 92 天存檔、開店前畫面，375 寬）：「−」「＋」30×30 共 116 顆、開關 46×28 共 39 個、「補滿」41×28——都比手指
（約 44）小。

**修法**：畫出來的按鈕不動；手指按得到的範圍往外多一點：「−」「＋」左右各 6、上下各 4（變成 42×38）；開關四邊各 4；「補到建議」
「補滿」左右各 2、上下各 4。多出來的量是「跟旁邊最近的按鈕距離的一半」（售價列和庫存列上下差 8，「補到建議」和「補滿」左右差 5），
所以兩顆按鈕的範圍不會重疊。

**證據**：
- `prep_before_390.png`／`prep_after_390.png`：修之前、修之後同一個位置的截圖，逐像素比對完全一樣（三個捲動位置都是）。
- 測試 `qa_the_prep_screens_small_buttons_take_a_finger`：375 和 430 寬，畫面上每一個「−」「＋」、開關、「補到建議」「補滿」，在
  多出來的範圍的四角、四邊中點按下去，都是那一顆、不是別顆。`mutants.txt`：修之前、範圍放大到互相重疊、開關沒有放大，三個都失敗。
- 只在桌面 Chromium 量過；iPhone Safari 上按鈕外面的範圍算不算按到，需要使用者在手機上試。

## 第二版（2026-10-13，完整回歸之後）

- **第一版在完整回歸被抓到**：`qa_the_screens_fit_375_390_430`（檢查畫面上有沒有被切掉的字）把「−」「＋」、設定頁的開關算成「內容比按鈕寬」
  （`screens_fit_failure_86820a6.txt`）——第一版是用一層透明的 `::before` 伸出按鈕外，這個檢查會把它當成被切掉的內容。這個檢查是對的
  （它要抓真的被切掉的字），所以不改它，改做法。
- **第二版**：按得到的範圍就是按鈕自己的框（「−」「＋」本來就沒有畫框；開關和「補到建議」「補滿」多出來的是框外一圈透明的邊，顏色只畫在
  原本的範圍），用負的邊距把多出來的位置還回去，排版不動。範圍的大小跟第一版一樣。
- **新的測試抓到第二版的一個真問題**：「−」「＋」往內放大的那一塊被中間的數字蓋住，按下去按到數字。讓按鈕疊在數字上面（`position:relative`）就好了。
- **測試跟著改的地方和原因**：第一版的測試量「按鈕的框再往外 6 px」——那是針對第一版的做法；第二版按鈕的框本身就是按得到的範圍，所以改成
  量框夠不夠大（「−」「＋」至少 42×38、招牌菜那一列 46×42、開關 54×36、「補到建議」「補滿」高 36），框裡的點都要按到它自己。取樣的點跟第一版
  一樣多；圓角按鈕的角落點取在圓弧上（圓角外面那一點，以前的開關也按不到）。
- `mutants_v2.txt`：修之前、「−」「＋」被數字蓋住、範圍大到上下兩列重疊、開關沒放大、「補到建議」「補滿」沒放大——五個都失敗。
